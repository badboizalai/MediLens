# Anonymisation checklist

Run for every note before it leaves the working copy. All boxes must be ticked; a second person checks if available. Never commit a note that fails.

- [ ] File name and heading use only the code (P01 / C01); no names in file names, metadata or commit messages.
- [ ] No names of people, including relatives, friends, doctors or interviewers (use codes or "a relative").
- [ ] No phone numbers, emails, social handles or addresses; places generalised to region level at most.
- [ ] No hospital, clinic, employer or school names.
- [ ] No record, insurance, national ID or patient numbers.
- [ ] Dates generalised (week or month; age band instead of birth date or year).
- [ ] Health details generalised or removed: no exact diagnosis, test values or treatment dates unless essential, and then generalised (for example "a chronic condition").
- [ ] Quotes paraphrased or trimmed so a colleague could not recognise the speaker.
- [ ] Rare combinations (unusual job + condition + place) removed.
- [ ] No screenshots, photos, audio, video or documents attached.
- [ ] Code-to-person key is not in the same file, folder or repo.
- [ ] Recording and raw notes deleted per the research plan; deletion week noted.
- [ ] Consent on file for the participant, and any withdrawal applied.
- [ ] Final scan: search the note for digit sequences, `@`, and capitalised names before storing.

Sign-off: checker code I__, week ____.
